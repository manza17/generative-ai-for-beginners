## 1. Dos clientes, dos APIs

| | Responses API (la más nueva) | Chat Completions |
|---|---|---|
| Cliente | `OpenAI(base_url="https://<recurso>.openai.azure.com/openai/v1/", api_key=...)` | `AzureOpenAI(azure_endpoint=..., api_key=..., api_version="2024-10-21")` |
| `api_version` | **No se usa** (endpoint v1) | **Obligatorio** |
| Método | `client.responses.create(...)` | `client.chat.completions.create(...)` |
| Entrada | `input=` (string o lista de mensajes) | `messages=` (lista de mensajes) |
| Límite de salida | `max_output_tokens=` | `max_tokens=` (razonamiento: `max_completion_tokens=`) |
| Leer la respuesta | `response.output_text` | `response.choices[0].message.content` |
| Historial | El servidor puede guardarlo (`previous_response_id`) | *Stateless*: lo reenvías completo |

En los dos casos, `model=` es el **nombre del deployment**, no el del modelo.

```python
# Responses API
client = OpenAI(api_key=os.environ["AZURE_OPENAI_API_KEY"],
                base_url=f"{os.environ['AZURE_OPENAI_ENDPOINT'].rstrip('/')}/openai/v1/")
r = client.responses.create(model=deployment, input=prompt, max_output_tokens=1024)
print(r.output_text)

# Chat Completions
client = AzureOpenAI(azure_endpoint=endpoint, api_key=key, api_version="2024-10-21")
r = client.chat.completions.create(model=deployment, messages=[{"role": "user", "content": prompt}])
print(r.choices[0].message.content)
```

## 2. Roles de los mensajes
- `system`: personalidad, reglas y límites (*metaprompt*).
- `user`: lo que escribe el usuario.
- `assistant`: respuestas anteriores. **Las puedes escribir tú** para dar ejemplos (*few-shot*), y el modelo las toma como propias.

## 3. Historial: `store` y `previous_response_id`
```python
first = client.responses.create(model=deployment, input="Define catastrophic forgetting.")
second = client.responses.create(
    model=deployment,
    previous_response_id=first.id,     # el servidor recupera el contexto
    input="Explain it for a college freshman.",
)
```
- **`store`** decide si el **servidor guarda** la respuesta.
  - ⚠️ `store=False` **no** cambia lo que envías: solo hace que el servicio no la guarde.
  - Consecuencia: **no se puede encadenar** con `previous_response_id`.
- Con `previous_response_id` **no reenvías** el historial, pero el contexto anterior **se sigue cobrando** como tokens de entrada.
- Con Chat Completions, el historial lo guarda **tu backend** (una lista `messages`) y se reenvía en cada llamada.

## 4. Salidas estructuradas
| Nivel | Qué garantiza |
|---|---|
| Formato pedido en el prompt | Nada: es una instrucción probabilística |
| `{"type": "json_object"}` | JSON válido, con **cualquier** estructura |
| `{"type": "json_schema", "strict": True, ...}` | JSON válido **con los campos y tipos** del esquema |

```python
# Chat Completions
response_format={"type": "json_schema",
                 "json_schema": {"name": "resumen", "strict": True, "schema": {...}}}

# Responses API → va en text.format, NO en response_format
text={"format": {"type": "json_schema", "name": "resumen", "strict": True, "schema": {...}}}
```
- El esquema usa `"required": [...]` y `"additionalProperties": False`.
- En producción, además se **valida en el código** (por ejemplo, con Pydantic).

## 5. Buenas prácticas de prompt (las de Azure OpenAI)
- **Separar las instrucciones del contenido** con delimitadores. Las instrucciones van **fuera** del delimitador.
- **Ser específico:** formato, largo, público y estilo.
- **Few-shot:** ejemplos de la salida deseada.
- ***Cues*:** empezar tú la respuesta. Funcionan peor en los modelos de chat que en la antigua Completion API.
- ***Double down*:** repetir la instrucción antes y después del contenido.
- **El orden importa** (*recency bias*).
- **Darle una salida al modelo** (*out*) para cuando no sabe: reduce las alucinaciones, pero no las elimina.

## 6. Trampas típicas
- Poner el **nombre del modelo** en lugar del nombre del deployment → `404 DeploymentNotFound`.
- Usar `AzureOpenAI` **sin** `api_version`, o ponerla con el endpoint `/openai/v1/`.
- Esperar `output_text` en Chat Completions, o `choices[0]` en la Responses API.
- `response_format` en la Responses API: allí es `text.format`.
- Pensar que `store=False` reduce lo que se envía o lo que se cobra.
- Modelos de razonamiento (como `gpt-5-mini`): `temperature` distinta de 1 da error, y en Chat Completions se usa `max_completion_tokens`.
- El modelo **no sabe la fecha de hoy**: se inyecta en el system prompt.
